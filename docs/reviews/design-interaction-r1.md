This is round 1. The UI is still half-built: `src/App.tsx` and `src/styles.css` are imported at `src/main.tsx:3-4` but don't exist yet. So I haven't run the build or any tests. The findings below cover only the plan and code that exists.

| # | Sev | Claim | Reality | Consequence | Fix / test |
|---|---|---|---|---|---|
| 1 | HIGH | Whitelists are never ignored (`PLAN.md:15`) | The worker instructions only say what a whitelist does in variations mode, not in single or repeat. The Lock/Vary toggle shows in every mode (`Library.tsx:19`). | A Vary setting in single mode is either silently dropped or picked at random. | The plan should either sample once per image or reject the request with an error. The UI should disable Vary outside variations mode and say why. Test: single mode plus a whitelist; the preview must contain a whitelisted value, or the UI shows the reason. |
| 2 | HIGH | Impossible image counts are rejected or repeats flagged | The preview response (`types.ts:10`) has no warnings or distinct-count field. | A user pays for 12 images from only 6 distinct combinations and finds the duplicates afterward. | Add `warnings` and `distinct_count` to `/api/preview`. Show "6 distinct; 6 repeats" before Generate. |
| 3 | HIGH | Errors are understandable | Job errors are untyped (`types.ts:12`). `api()` only reads a plain error string (`lib.ts:43`). | A partially failed job can't say which image failed, and a conflict error can't point to the attribute that caused it. | Define per-image errors (index, selections, message, retryable) and a 400 body that names the attribute. Add "Retry failed only". Test: mock 1 of 4 failed. |
| 4 | MED | Lock and Vary behave differently | Switching Vary to Lock keeps only the first value and drops the rest silently (`lib.ts:34`). Vary with one value is accepted. | Choices vanish with no message, and a one-value "Vary" is really a lock. | Show a "2 values removed" notice and a "Pick 2+ to vary" hint. |
| 5 | MED | The chosen mode sticks | The Lock/Vary preference lives only in the component (`Library.tsx:9`). | An empty Vary resets to Lock after switching category and coming back. | Store it in the draft. Test: switch category and back; Vary is still pressed. |
| 6 | MED | Presets and draft are saved to the browser | `writeStorage` is an empty stub (`lib.ts:7-8`). Stale IDs are removed silently. | Nothing persists. | Implement saving, and show "N saved values no longer exist" when IDs are removed. |
| 7 | MED | Value controls are accessible | The value name used as the accessible label replaces the description (`Library.tsx:17`). The "None" button has no pressed state for screen readers (`Library.tsx:19`). | Screen-reader users hear the name but not the steering text, and can't tell when "None" is active. | Point the control's description at the description text and add a pressed state to "None". Run an axe check with 0 violations. |
| 8 | MED | Library search finds values | Search only covers the current category (`Library.tsx:23`) and hides selected values (`Library.tsx:13`). | Searching from the wrong category shows "No matching attributes". A selected value can disappear from view. | Search across all categories with match counts in the nav, and always show selected values. |
| 9 | MED | The gallery filters on every attribute and value | The plan has no rules for filter chips, clearing, or resetting the page. Old imported images have no tags. | 750+ checkboxes is unusable. Filtering on page 3 can show an empty page. Untagged images vanish with no explanation. | Use a searchable picker with removable chips and "Clear all". Announce the result count to screen readers. Reset to page 1 on any change and keep filter state in the URL. Explain that untagged images are excluded. |
| 10 | LOW | Detail dialog and reuse | Not built yet. The plan doesn't say where focus goes on close or whether reuse overwrites the draft. | Focus is lost after closing, and reuse can wipe unsaved work. | Give the dialog a title and return focus to the thumbnail that opened it. Make reuse undoable. Alt text should be selection names plus ratio, not the raw prompt. Test: open, Esc, focus is back on the thumbnail. |
| 11 | LOW | Broken thumbnails fail Slice 1 | The thumbnail fallback (`UI.tsx:16`) replaces a broken image with a letter. | It hides exactly the failure Slice 1 is meant to catch. | A test walks every category and asserts zero fallbacks and no image load errors. |
| 12 | LOW | Booleans have explicit on and off | The `camera` boolean has only `on`, and the "On / off" label is hard-coded. Check with the `python3 -I -c …` command in the plan file. | The UI promises an "off" that doesn't exist. | The library worker fixes the data, the UI builds the label from the actual values, and `test_library.py` asserts exactly on and off. |
